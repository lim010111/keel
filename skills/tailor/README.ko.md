# Tailor

지금 보내려던 프롬프트를, **그 프롬프트를 실행할 모델에 맞춰** 다시 써주는
Claude Code 플러그인입니다.

    /tailor:gpt-5-6-sol  <프롬프트>
    /tailor:opus-5       <프롬프트>
    /tailor:opus-4-8     <프롬프트>
    /tailor:fable-5      <프롬프트>

콜론 뒤의 이름은 **당신의 프롬프트를 실행할 모델**입니다. 다시 쓰는 쪽 모델이
아닙니다. 돌려주는 프롬프트는 당신이 실제로 실행할 곳을 위한 것입니다.

**OpenAI Codex CLI에서도 같은 프로필로 동작합니다.** Codex는 스킬을 `/`가 아니라
`$`로 호출합니다 — `$tailor:gpt-5-6-sol <프롬프트>`.

**모델은 계속 추가됩니다** — Gemini, Grok, 오픈웨이트 계열까지.

## 왜 필요한가

**같은 프롬프트가 모든 모델에서 같게 동작하지 않습니다.** 모델을 만든 회사들이
자기 모델을 어떻게 프롬프팅해야 하는지 가이드를 내는데, 그 조언들이 실제로
서로 어긋납니다.

- Claude Opus 5는 시킨 것보다 **더** 하는 쪽입니다 — 단계를 더 밟고, 확인을 더
  하고, 답이 길어집니다. 그래서 좋은 프롬프트는 선을 그어줍니다. 무엇이 범위
  밖인지, 무엇은 손대지 말아야 하는지.
- Claude Opus 4.8은 시킨 것을 **딱 그만큼만** 합니다. 첫 번째 섹션을 고치라고
  하면 정확히 첫 번째 섹션만 고칩니다. 그래서 좋은 프롬프트는 각 지시가 어디까지
  미치는지 밝혀줍니다.
- GPT-5.6은 **덜어낼수록 실제로 더 잘합니다.** OpenAI가 직접 낸 수치가 그렇습니다
  — 간결한 프롬프트가 비용만 아끼는 게 아니라 평가 점수 자체를 올립니다.

요청 하나에 서로 다른 세 가지 다시 쓰기가 나옵니다. 그런데 터미널에 한 문장
치자고 벤더 가이드 네 개를 읽는 사람은 거의 없고, 읽었더라도 타이핑하는 동안
머릿속에 들고 있지는 못합니다.

**에이전트의 하네스가 이걸 없애주지도 않습니다.** Claude Code나 Codex가 당신
메시지 주위에 자기 지시를 감싸는 건 맞습니다. 하지만 당신이 친 그 문장은 여전히
모델이 읽는 것 중 가장 큰 덩어리이고, **당신의 실제 작업을 설명하는 유일한
부분**입니다.

**그리고 그 문장은 대개 설익어 있습니다.** 다른 걸 생각하던 와중에 빠르게 치거나,
받아쓰기(Wispr Flow, 음성 입력)로 넣어서 군말과 오타까지 얹힙니다. 빠지는 건
거의 항상 같은 것들입니다 — 어느 파일인지, 무엇이 "완료"인지, 무엇은 건드리지
말아야 하는지. 모델은 그 빈칸을 추측으로 메우고, 모델마다 다르게 추측합니다.

Tailor는 그 간극을 커맨드 하나로 메웁니다.

## 무엇을 돌려받는가

세 가지입니다.

1. **다시 쓴 프롬프트** — 복사할 수 있는 깔끔한 블록 하나. 새 세션에서 실행하세요.
   그래야 모델이 이 대화가 아니라 정리된 버전에서 출발합니다.
2. **무엇을 추측했는지** — 대신 채워 넣은 범위와 의도. **여기가 제일 쓸모 있는
   경우가 많습니다.** Tailor는 멈춰서 당신을 심문하지 않습니다. 대신 추측한 걸
   적어두니, 실행하기 전에 틀린 것만 골라 고치면 됩니다.
3. **effort 노트** — 작업이 그럴 만큼 클 때만. 어느 reasoning 설정이 이 실행에
   맞는지 알려줍니다.

**당신이 요청한 것 자체는 바뀌지 않습니다.** Tailor가 채우는 건 당신이 말하지
않고 넘어간 부분입니다 — 어느 파일인지, 무엇이 "완료"인지, 무엇은 그대로 둘지.
요청한 그 일이 돌려받는 그 일입니다. *설명해달라*가 슬쩍 *고쳐달라*로 바뀌거나,
없던 목표가 붙는 일은 없습니다.

대신 당신이 친 것보다 **더 구체적으로는 만듭니다.** 그게 이 도구의 일이니까요.
다만 프롬프트가 이미 어느 파일인지, 무엇을 바꿀지, 무엇을 둘지 말하고 있다면,
거의 그대로 돌려주면서 그렇다고 적어줍니다.

작업을 대신 실행하지도 않습니다. 한 번 답하고 멈춥니다.

## 무엇이 다른가

**모든 프로필은 그 모델의 공식 프롬프팅 가이드에서 직접 저술됩니다.** 가이드
URL과 **그 문서를 읽은 날짜**가 프로필 안에 함께 박혀 있어서, 눌러서 들어가 어떤
조언이든 출처와 대조해볼 수 있습니다. Tailor는 모델이 뭘 좋아할지 짐작하지
않으며, 그 말을 믿어달라고 하지도 않습니다.

**그냥 `/tailor`는 일부러 없습니다.** 대상 모델을 반드시 지목해야 합니다. 의도된
마찰입니다 — 기본값을 두면 모델이 바뀌는 동안 조용히 낡고, 어느새 GPT 실행에
Opus 4.8용 조언이 적용되는데도 눈치채지 못합니다. 모델을 지목하는 행위가 바로
그 다시 쓰기를 값어치 있을 만큼 구체적으로 만듭니다.

## 설치

**Claude Code** — 설치 후 `/tailor:<모델> <프롬프트>` 로 호출합니다.

```
/plugin marketplace add lim010111/prompt-tailor
/plugin install tailor@lim010111-plugins
/reload-plugins
```

**Codex CLI** — 설치 후 `$tailor:<모델> <프롬프트>` 로 호출하거나 `/skills` 에서
프로필을 고릅니다.

```
codex plugin marketplace add lim010111/prompt-tailor
codex plugin add tailor@lim010111-plugins
```

## 구성

- `method.md` — **공유 코어**. 벤더와 무관하게 모든 프로필이 쓰는 방법론입니다
  (부족한 만큼만 다시 쓰기, 가정 나열, 3부 출력, 무엇을 덜어낼지, 예제). 플러그인
  루트에 있습니다.
- `skills/<model>/SKILL.md` — **모델 버전당 프로필 하나**. 어느 플러그인 시스템도
  코어를 프로필에 자동으로 이어붙이지 않기 때문에, 각 프로필이 호출 시점에 명시적
  지시로 코어를 읽어들입니다 — 없으면 안 되는 지시이니 지우지 마세요. 지시는 **같은
  파일을 두 경로로** 가리킵니다. `${CLAUDE_PLUGIN_ROOT}/method.md` 는 Claude Code가
  플러그인 루트의 절대경로로 치환하는 형태이고(2.1.198에서 확인 — 공식 문서는
  hooks/MCP 용도로만 적어두고 있습니다), `../../method.md` 는 프로필 기준 상대경로로
  Codex가 쓰는 형태입니다. Codex에는 플러그인 루트 변수가 아예 없고, 상대 참조가
  공식 문서에 적힌 방식입니다. 두 경로는 같은 파일로 수렴합니다. 기각된 세 번째
  대안(2.1.198에서 확인): bash 주입(`` !`cat …` ``)은 headless `-p` 실행에서 호출
  전체를 조용히 죽였습니다.
- `skills/<model>/agents/openai.yaml` — 해당 프로필의 Codex 호출 정책입니다.
  `allow_implicit_invocation: false` 로 두어 모델이 스스로 발동시키지 못하게 합니다.
  Claude Code frontmatter의 `disable-model-invocation: true` 에 대응하는 파일이고,
  그 필드는 Codex가 무시합니다. Tailor는 양쪽 모두에서 사용자 호출 전용입니다.
- **플러그인 매니페스트가 두 벌인 건 의도입니다.** `.claude-plugin/`(`plugin.json`
  + `marketplace.json`)이 Claude Code용, `.codex-plugin/plugin.json` 과
  `.agents/plugins/marketplace.json` 이 Codex용입니다. 한 트리에 같이 있어도 두 CLI
  모두 문제 삼지 않습니다. Codex는 `.claude-plugin/marketplace.json` 도 읽기는
  합니다 — 문서화되지 않은 동작입니다 — 그런데 **스킬 0개로 설치해놓고 끝까지 성공
  했다고 보고**하므로, 실제로 동작하게 만드는 건 Codex 매니페스트 쪽입니다. 두
  `plugin.json` 의 `version` 은 항상 같이 올리세요.

## 프로필 규율 (버전 고정, 문서 기반)

- **모델 버전에 고정하고, "최신"에는 절대 고정하지 않는다.** 프로필은 추가하고
  제거할 뿐 "최신 모델에 맞춰 갱신"하지 않습니다 — 움직이는 대상이야말로 조언이
  애초에 쓰이지 않은 모델에 적용되는 경로입니다. 프로필이 지목한 버전은 고정이지만
  **그 뒤의 벤더 문서는 고정이 아닙니다.** 벤더는 출시 이후에도 이 페이지들을
  실제로 개정하므로, 모든 프로필은 저술 출처 URL과 그 URL을 읽은 날짜를 기록합니다.
- **프로필 이름에 점을 쓰면 안 된다.** Claude Code의 커맨드 토크나이저가
  `/tailor:opus-4.8`을 해석하지 못합니다(직접 입력이든 headless든; 2.1.198에서
  확인 — 그 줄이 그냥 평문으로 모델에 흘러갑니다). 버전의 점은 대시로 적으세요:
  `opus-4-8`.
- **새 모델** → `skills/<token>/SKILL.md`를 추가하되 **그 모델의 공식 프롬프팅
  가이드에서** 저술하고, URL을 프로필 안에 박아 인용합니다. 제품·하네스 레벨
  지침(진행 상황 서술, 서브에이전트 한도, 클라이언트 타임아웃, 메모리 시스템)은
  넣지 마세요. 단발성 프롬프트 하나는 그런 게 들어갈 자리가 아닙니다.
- **새 계열**(Gemini 등) → `skills/<token>/SKILL.md` **하나만** 추가합니다.
  **벤더별 코어는 일부러 두지 않습니다** — `method.md`는 Tailor 자신의 다시 쓰기
  방법론이지 모델 가이드가 아니라서, 벤더별로 갈릴 이유가 없습니다. 실제로 갈리는
  것들(effort 사다리, thinking·verbosity 노브, 계열 고유의 함정)은 이미 모델을
  지목한 프로필 안에 있습니다.
- **퇴역한 모델** → 해당 프로필 디렉터리를 제거합니다.
- 코어에는 **움직이는 지시어**(`latest` / `flagship` / "현재 모델")를 쓰지 않습니다
  — 기본값을 없애서 제거한 낡음을 그대로 되살리는 표현이기 때문입니다.
- **메타 프롬프트 규칙:** 여기 있는 모든 파일은 당신의 현재 세션이 돌리는 모델
  위에서 실행됩니다. 어느 파일에도 자기 추론을 되읊게 하는 표현을 넣지 마세요 —
  모델에게 자기 reasoning을 재현하라고 시키면 일부 대상에서 거부를 유발합니다.

## 개발

이 저장소는 **미러**입니다. 원본은 작성자의 `~/.claude/skills/tailor/`이고, 그
디렉터리가 곧 skills-directory 플러그인입니다 — `.claude-plugin/plugin.json`을
갖고 있어서 Claude Code가 그 자리에서 `tailor@skills-dir`로 적재합니다. 개발 중에는
설치 단계가 필요 없습니다. 참고:
<https://code.claude.com/docs/en/plugins-reference> (§ Skills-directory plugins).

발행된 플러그인을 설치하면 그 개발본이 **가려집니다** — 이름이 겹치면 설치된
플러그인이 이기고, Claude Code는 `tailor@skills-dir: Not loaded`라고 보고합니다.
다시 작업 트리로 개발하려면 마켓플레이스 사본을 제거하세요.

미러를 갱신하려면:

```
rsync -a --delete --exclude='.git' ~/.claude/skills/tailor/ .
```
